# Audit A — deskd, the window engine, and i3 (15 October 2026)

Read-only review of the requested sources and rounds 66, 68 and 69. I read the setup documentation and the 10 October audit; findings fixed since that audit are not repeated. I ran the permitted Xephyr harness three times total: one `make test-deskd` run stopped at the first panel veil check; two direct runs of the same harness with `--keep` completed, one with that panel failure and one entirely green. Both completed runs passed keep-above. Temporary harness output was inspected and removed. No live display input or system configuration was changed.

`verified` means observed in a run or an exact code path; `inferred` means the consequence follows from code but was not reproduced on the live desktop. Effort: S = small, M = medium, L = large.

| A1 | **risk** | **Keep-above's reported 2/6 flake is not isolated by the test.** The test sends an EWMH message, sleeps 300 ms, focuses `cid` (which the preceding Alt+Tab check already focused), sleeps 500 ms, then samples the X stack. `raise_above` runs only in a deferred refresh. | A4 | **risk** | `hold_fitted` can miss a late application resize immediately after a workspace switch. | A5 | **risk** | `frame_of` caches a client's parent frame until the client closes. | A6 | **risk** | The global X error handler silently ignores *all* protocol errors, including errors from deskd's own `ConfigureWindow`, `MapWindow`, GC and paint requests. ## Top 5 by value/effort

1. A7: unmap layers when plugin geometry disappears.
2. A9: include sharing in click/audio layer visibility.
3. A2: exclude notifications from Alt+Tab.
4. A4: queue the fitted-window check after suppressed frame configures.
5. A8 and A11: prune retained IDs/classes in their existing cleanup paths.

## What I did not cover

- I did not exercise a physical `HDMI2` connect/disconnect, i3 restart, Zoom share session, or live applications on display `:0`.
- The historical keep-above failure did not recur in the two completed harness runs, so A1 remains a specific, testable race hypothesis rather than a confirmed root cause.
- The i3 cores lack symbols and their temporary nested config is gone; the crashing i3 function and triggering command remain unknown.
- I did not run `deskd_bench.py` because the audit found no new performance regression requiring another nested display run; its previous request counts remain documented in round 66.
