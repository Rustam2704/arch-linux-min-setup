# deskd bug review

Static review of `deskd.py`, `switcher.py`, and `panels.py`. i3 command behavior was checked against i3 4.25's command and floating-window implementations. The known resize-handle container-id bug is excluded.

1. **`deskd.py:2925-2933` — refitting steals focus.** `refit_all()` calls `maximize()`/`snap()` for every fitted window, and `fit()` focuses each one (`deskd.py:1961`). **Scenario:** start deskd or connect a monitor while several workspaces contain fitted windows → 600 ms later the visible workspace/focus jumps to the last fitted window in tree order. **Confidence: high.** Fix: preserve the original focused container/workspace and restore it after the batch, or let refits skip the final `focus` command.

2. **`deskd.py:777-783` — changed panel geometry leaves an old veil mapped.** Replacing `self.veils[frame.id]` creates a new `PanelDim` but never unmaps or destroys the previous X window. **Scenario:** resize or move the panel while keeping its frame → the old dark veil remains at its previous rectangle and the new one appears too, so the panel or desktop is darkened twice; repeated reflows accumulate X windows and graphics contexts. **Confidence: high.** Fix: destroy the prior veil (and remove its cached GC) before replacement; also destroy removed-frame veils rather than only unmapping them.

3. **`deskd.py:2566-2583` — removed workspace strips leave live click windows.** `place_ws_clicks()` only adds or moves layers for current plugin IDs; it never removes IDs absent from `strip_plugins()`. **Scenario:** restart/rebuild xfce4-panel so genmon gets a new ID → the old invisible InputOnly layer still covers the former strip position and clicking there switches workspaces, even if an unrelated control is now underneath. **Confidence: high.** Fix: destroy obsolete click windows and clear `click_by_win` and `strip_geoms` entries when the plugin set changes.

4. **`deskd.py:1011-1022,1079-1088` — i3 restart relabels marks but loses restore state.** `normalize_marks()` changes `_deskd_*_<old id>` marks to the new con ID, while saved rectangles and workspace names remain indexed by the old ID. **Scenario:** maximize a window, restart i3 in place, then restore it → the original rectangle is missing and `restore()` gives it a generic centered size; minimized windows also lose their saved placement. **Confidence: high.** Fix: when relabeling a mark, migrate the corresponding `state["windows"]` entry from its old ID to the new ID before saving.

5. **`deskd.py:3008-3025,2036-2045` — restoring after moving a fitted window can send it back to the old monitor.** `to_output()` preserves the saved rectangle from the first monitor; `restore()` accepts it whenever its centre lies on *any* connected output. i3's `move position` then reassigns the window to that output. **Scenario:** maximize on laptop, use Super+Shift+Right to move to the connected monitor, then restore → it jumps back to the laptop instead of restoring on the monitor. **Confidence: high.** Fix: translate or centre the saved rectangle on the destination output during `to_output()`, and validate restore rectangles against the window's current output.

6. **`deskd.py:2064-2069,3083-3087` — minimized dialogs appear as independent Alt+Tab entries everywhere.** `minimize()` marks an owner's dialogs and moves them to scratchpad without saving a workspace for them; `cycle()` admits minimized windows whose saved workspace is `None`. **Scenario:** minimize an app with an open modal dialog, switch to another workspace, press Alt+Tab → the dialog appears in that workspace's switcher; choosing it reveals the dialog while its owner stays hidden. **Confidence: high.** Fix: exclude dialogs tied to a minimized owner from the switcher, or store and restore the owner/dialog group together.

7. **`deskd.py:1169-1174,3074-3095,3099-3110` — Alt+Tab can select a window closed during the round.** The close handler removes its icon but does not remove its entry from `self.alt_tab["order"]`. **Scenario:** hold Alt to show the switcher, close a listed window by another means, select that entry, release Alt → i3 refuses the stale con ID and no switch occurs; the dead entry remains visible until release. **Confidence: high.** Fix: remove closed con IDs from the active round and adjust its index, ending the round if fewer than two entries remain.

8. **`panels.py:138-162` — changing main-panel settings does not update screen copies.** `signature()` compares only plugin types and command names, so `plan()` regards a copied panel as current even if its font, size, layout, launcher contents, or plugin settings differ. **Scenario:** change a main-panel plugin setting and keep the same plugins → the external monitor's panel retains the old setting indefinitely. **Confidence: high.** Fix: include copied property values and relevant rc/launcher content in the comparison, or refresh those properties on existing copies.

9. **`deskd.py:2026-2045` — saved rectangles can restore mostly off-screen after a resolution change.** The fallback runs only when one point near the rectangle's centre is outside *all* outputs; it never checks that the full frame fits the current work area. **Scenario:** maximize a wide window, reduce that monitor's resolution, then restore → its old top-left and size are reused if the centre still falls on the display, leaving edges or controls off-screen. **Confidence: high.** Fix: clamp the entire saved frame to the current output's work area, reducing size where necessary.

10. **`deskd.py:2625-2634` — fullscreen on a second monitor makes the active-workspace mark flicker on the first.** For every busy panel, `hide_over_fullscreen()` hides the single global `ws_mark` and mark file, without checking which output holds the focused workspace. **Scenario:** keep a fullscreen video on the external display and work on the laptop → each refresh clears the laptop's flame/mark until the delayed `place_ws_clicks()` timer restores it about 400 ms later. **Confidence: medium.** Fix: hide the mark only when its focused output is busy; update the mark once after evaluating all panels.

11. **`deskd.py:2600-2611,2635-2645` — screen sharing leaves invisible input layers active.** `set_sharing(True)` hides veils and the mark but does not unmap workspace-strip or audio InputOnly windows. **Scenario:** Zoom's share frame covers the top edge where a layer sits → clicking that area switches workspace or operates volume instead of reaching the share UI underneath. **Confidence: medium.** Fix: apply the sharing flag when showing click and audio layers, then restore them according to fullscreen state when sharing ends.

12. **`deskd.py:725-745` — a missing audio wrapper leaves its old click target active.** When a plugin ID still exists in xfconf but `plugin_geometry(pid)` returns `None`, the loop continues without hiding its existing `audio_layers[pid]`. **Scenario:** xfce4-panel crashes or briefly remaps that plugin, leaving its configuration intact → the transparent audio layer remains at its old coordinates and intercepts mouse wheel/clicks there. **Confidence: medium.** Fix: unmap or destroy the layer whenever its wrapper cannot be located; remap it after a fresh geometry is found.

13. **`deskd.py:599-608` — `ensure_primary()` accepts the wrong primary output.** It returns as soon as *any* ` primary ` text appears in `xrandr --query`, without checking that the primary output is eDP/LVDS. **Scenario:** an external display is marked primary, then the monitor set changes → deskd leaves the external display primary and the main panel/workspace numbering follows it, despite the laptop-primary rule. **Confidence: medium.** Fix: identify the current primary by name and explicitly set the connected laptop output primary when it differs.

14. **`deskd.py:2095-2102` — “unminimize last” chooses tree order rather than the last minimized window.** The function takes the first `_deskd_min` mark yielded by `walk(tree)`; no minimization order is recorded. **Scenario:** minimize A, then B, press Super+Shift+Minus → A can reappear instead of B, depending on i3 tree order. **Confidence: medium.** Fix: keep a most-recently-minimized con-ID stack and remove entries on restore/close.

15. **`deskd.py:2817-2822,2853-2859` — output-block allocation can exhaust permanently.** `block_for()` retains mappings for vanished outputs and uses `next()` over only ten block IDs before `outputs_changed()` can consider orphan reuse. **Scenario:** use enough differently named monitor outputs over time, with old outputs leaving no surviving workspace to reclaim → connecting the next output raises `StopIteration`, so output setup and panel synchronization abort. **Confidence: low.** Fix: reclaim inactive output mappings before allocation, or allocate beyond the fixed ten-block range with an explicit collision policy.
